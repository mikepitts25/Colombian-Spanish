# Authored production exercises

`src/exercises/production.ts` provides a deterministic offline engine. It is not yet connected to a learner-facing player. No bundled teaching exercises or editorial approvals were added by this package.

A definition has schemaVersion 1, a stable id, positive contentVersion, source cardId/deckId, kind (`typed-recall` or `cloze`), prompt, nonempty acceptedAnswers, correction explanation and up to five ordered hints. Cloze prompts contain exactly one `{{blank}}`; accepted answers contain only the missing phrase. Revise contentVersion when teaching content changes. IDs should stay stable across editorial corrections. The engine validates structure, not linguistic correctness or whether the source card actually exists; the future pack loader must validate references and current editorial acceptance before release.

List accepted alternatives explicitly after editorial review. Do not split card fronts at slashes or infer synonyms. The engine accepts case, Unicode composition/compatibility, whitespace and outer sentence punctuation variations. It preserves word order, internal punctuation, accents and ñ. Vowel-accent-only differences produce an incorrect `accent` result for a focused correction; ñ/n differences are ordinary incorrect answers. Empty input is unanswered and must not advance the player or create an event.

Call `productionHint(exercise, hintsUsed)` to reveal the next authored hint. Keep the returned count with the current attempt; exhausted hints return null. A correct response after a hint is assisted (`independent: false`). Do not count assisted correctness as unaided recall. The correction exposes an exact accepted variant where possible, otherwise the nearest vowel-accent variant or the first authored answer, together with the authored explanation.

On submission, construct one `createProductionObservation` with stable session ID, nonnegative integer attempt, current answer/hint count, timestamp and finite nonnegative elapsed duration. Retain this exact observation during `appendLearningEvent` retries. Reusing its ID with another result is a conflict, not a new attempt. A deliberate new answer attempt increments the attempt identity. Duplicate retention is bounded by the existing 5,000-event local history; this is not a permanent receipt service.

The observation stores answer-checked recall, outcome, hint count, duration and exercise ID/kind/contentVersion. It stores no raw response or prompt. It does not alter the source card's SRS, daily goal, seen-word history or streak. Version-3 backups retain provenance. Old histories without exercise metadata remain readable. Consumers should combine `modality`, `evidence` and `hintsUsed` before describing an independent performance result. Human review of teaching content, accessible player integration, simulator checks and actual learning measurement remain required.
