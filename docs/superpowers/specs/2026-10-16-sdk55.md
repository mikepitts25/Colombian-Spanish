# Expo SDK 55 migration design

Purpose: continue B01.8-C2 through the next supported SDK step while preserving learning state and application flows. This is maintenance within the authorized AI roadmap, not a redesign or release publication.

Use Expo 55 stable (registry sdk-55 tag55.0.31), its coordinated RN 0.83/React 19.2/module/test preset family, default Hermes and existing Navigation7. No canaries, legacy-peer-deps or blanket audit-force. Follow Expo's incremental upgrade workflow: https://docs.expo.dev/workflow/upgrading-expo-sdk-walkthrough/ and https://expo.dev/changelog/sdk-55 . Investigate installed versioned module types/source when archived docs redirect. Keep native recording excluded outside development.

Keep all AsyncStorage schemas/keys and content unchanged; preserve old backups, exact queues, mission checkpoints and modality evidence. Isolate Expo update compatibility by moving runtime policy from appVersion to fingerprint; do not publish an OTA or binary. Revisit the exact-parent PostCSS override when parent changes; retain a scoped fix only if actual installed PostCSS remains affected. Re-audit rather than assume migration fixes all findings.

Success: aligned packages, clean install, full/calendar suites, type/lint/format/content checks, both native project generation and production JS exports, available native iOS compilation and dedicated simulator state/navigation/audio/backup checks, one fresh review and regression fixes. No microphone grant without explicit approval, no Android runtime pass without SDK/license/tooling, no signed release or physical-device inference. Keep unverified upgrade work off main.
