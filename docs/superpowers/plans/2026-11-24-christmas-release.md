# Colombian Spanish · Pre-Christmas 2026 implementation checklist

**Goal.** Ship a dependable iPhone and iPad experience that helps a beginner do one useful thing in Colombian Spanish, rewards a second visit, and sells a clearly defined permanent library if it earns its price. iOS first and December 17 are planning assumptions. Android remains a later release track unless the owner adds it.

**Read first.** The [screen audit and product decisions](../../product/2026-11-24-christmas-release-audit.md) cover all 26 screens, the major secondary states, interaction hierarchy, business case and pilot metrics. The [master plan](../../../MASTER_PLAN.md) contains earlier milestones. This checklist governs the proposed Christmas slice.

## How to call a smaller model

> Open `docs/superpowers/plans/2026-11-24-christmas-release.md`. Execute **[ticket ID] only**. Read its matching screen rows in the linked audit and only the named code/tests first. Check the current branch for existing work. Follow established behavior and the ticket's acceptance checks. Run the named focused tests and typecheck for code edits. Inspect the actual render for UI changes. Report changed files, commands, results and outstanding device/editor/owner evidence. Check off only the evidence you obtained. Stop at any external action explicitly reserved for another owner.

For the first call, use **C0** to produce the inventory and the scope decision for the owner. **U1** is the first learner-facing engineering ticket. Start a fresh context for each ticket. Paths below are repository-relative. Screen names under “Touch” mean `src/screens/<Name>Screen.tsx`. Shared strings live in `src/i18n/translations.ts`. For a named screen test use `npm test -- --runInBand --watchman=false --runTestsByPath __tests__/screens/<Name>Screen.test.tsx`. Specific exceptions are named in the tickets. Use `npm run typecheck` for changed TypeScript. Combine tasks only when they touch the same file and fit one test cycle.

**Priorities.** P0 is required for the chosen release scope. P1 is the core experience polish, ordered by learner impact. P2 is a stretch item. An editor signs language decisions, the owner selects the offer and controls publication, and a hardware tester runs device checks. An implementation agent can prepare fixtures, patches, observations and evidence for each.

**Deliberate cuts.** Additional six neighborhood visits can follow after the initial pair. Offer only accepted prerequisites. The fallback if both visits miss review is a truthful flashcard/phrase release **only if** its catalogue clears C2, its first-use pilot demonstrates value and the owner accepts that positioning. A free-only candidate removes marketing, buy CTAs and unavailable-store panels for unoffered content; it preserves genuine existing entitlement/legacy access, backups and core learning. Unresolved paid access for existing customers holds that build. The last fallback is to continue internal testing.
