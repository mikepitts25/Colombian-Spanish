SDK reads establish America/Anchorage, October19 evening, with app PID1662 retained. Foregrounding the old code keeps its October20 morning greeting and daily3; all nine saved records remain unchanged. A temporary read-only [clock diagnostic](native-clock-diagnostic.json) establishes the cause: `Date` reports October20/GMT+0200/offset−120 while a fresh `Intl` formatter resolves America/Anchorage at the same UTC instant. No raw app contents are logged. The diagnostic is removed from final source.

Current-zone calendar keys now use a fresh Gregorian/Latin-digit `Intl.DateTimeFormat`, instead of cached native Date getters. Home greeting uses the same current-zone hour, and daily-word identity uses the shared calendar key. Newly generated morning reminders resolve each future local8am using that date's offset, so crossing DST does not carry today's offset forward. Existing reminder permissions, seven-day window and refresh-on-launch policy remain unchanged; this does not prove delivery or automatic rescheduling of already queued notifications while the app stays open.
