## Added integration evidence

The new suite runs real parser/restore/portable-state/durable-storage boundaries with the existing official AsyncStorage Jest adapter. A constructed old-format v3 file supplies seven state sections, a custom scheduled/favorite card and no mission/plan fields. Local state starts with English preferences, canonical streak 42, stale legacy streak 99 and a newer local observation; incoming state requests Spanish, canonical streak 8 and empty incoming history.

Holding canonical streak writes fails after earlier after-images have been applied. An eleven-entry durable journal remains. A normal `loadDecks` read fails again while the same fault remains; the complete partial raw state stays identical. Once allowed, coherent snapshot access replays the intended state, retains the local observation, supplies empty optional checkpoints and clears the journal. The canonical streak becomes 8 while stale legacy 99 remains ignored. Repeating the same restore keeps the same supplemental state and one observation; the supplied source remains unchanged.

Separate malformed JSON/unsupported-schema local-history cases begin with nonempty scheduled custom content and full supported state. Valid incoming replacement is refused before preparing a journal. All raw keys, including legacy state and custom card scheduling, remain unchanged. These are synthetic compatibility fixtures, not tests of third-party file providers.
