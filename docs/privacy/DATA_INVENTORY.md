Draft mission checkpoints live under `SRS_MISSIONS_V1` (`src/storage/missions.ts`) and retain run/content/node IDs, revision, option/accepted-variant index feedback, hints, assistance/playback flags, review-card IDs and idempotency receipts. They do not retain raw typed answers or transcript text. They are included in optional mission state during version-3 backup, restore and journal recovery; old seven-section files are supported. The bundled authored content remains available separately.

## Diagnostics tradeoff and release checks

Application error content and frame paths/function names are intentionally dropped; stack frames retain numeric positions with a generic bundle name. This reduces debugging detail and may limit source-map grouping. Native crash collection is disabled until its payload path is separately audited. This is deliberately scoped JavaScript reporting, not a claim that native crashes are observed.

Before enabling a DSN in a shipped build, the owner must inspect an actual captured event/envelope, confirm no learning content or identities appear, verify project access/retention/IP handling, confirm desired collection behavior and complete matching store disclosures. No production project settings were changed by this audit. Contact information and any release-specific legal/consent decisions remain owner work.
