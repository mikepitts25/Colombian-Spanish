Draft mission checkpoints live under `SRS_MISSIONS_V1` (`src/storage/missions.ts`) and retain run/content/node IDs, revision, option/accepted-variant index feedback, hints, assistance/playback flags, review-card IDs and idempotency receipts. They do not retain raw typed answers or transcript text. Active applied timing checkpoints retain accumulated milliseconds and an optional active interval anchor; these are activity measurements, not voice recordings or raw responses. Mission runs are included in optional mission state during version-3 backup, restore and journal recovery. `SRS_DAILY_PLAN_V1` separately retains the plan identity, phase and linked review/applied references described above.

Current version-3 file snapshots contain nine supported application-state sections (dailyPlan, missions, prefs, daily, streak, seenWords, quizHistory, lastSession and notificationPrefs), plus decks and learning events. The full restore journal can therefore contain eleven after-images. Legacy seven-section application state remains accepted with optional mission/plan handling. Clipboard export remains version 2 (decks/events), so it does not carry these supplemental sections. The bundled authored content remains available separately. A file backup does not carry OS permissions, notification schedules, cache audio or a signed build configuration.

## Diagnostics tradeoff and release checks

Application error content and frame paths/function names are intentionally dropped; stack frames retain numeric positions with a generic bundle name. This reduces debugging detail and may limit source-map grouping. Native crash collection is disabled until its payload path is separately audited. This is deliberately scoped JavaScript reporting, not a claim that native crashes are observed.

Before enabling a DSN in a shipped build, the owner must inspect an actual captured event/envelope, confirm no learning content or identities appear, verify project access/retention/IP handling, confirm desired collection behavior and complete matching store disclosures. No production project settings were changed by this audit. Contact information and any release-specific legal/consent decisions remain owner work.

## Development-only voice preview

`src/screens/VoicePracticeScreen.tsx`, `src/speaking/voicePractice.ts` and `src/services/voicePractice.ts` implement explicit local microphone permission, one cache take, Stop/replay/delete and an unscored text alternative. Native capture is bounded to 30 seconds; replay accepts at most 2 MiB. No upload, transcript, score, event or backup inclusion. Owned cache files are deleted on explicit Delete or attempted on exit; failure preserves retry state, process termination can leave files. `app.config.js` blocks native recording permissions except the development build profile. The [SDK55 native QA](../qa/2026-10-16-sdk55/REPORT.md) subsequently verified authorized iOS development-client capture, manual Stop/replay/Delete, auto-stop and Back cleanup, with zero retained recording files at its final checkpoint and unchanged learning counts. That bounded simulator result does not validate physical audibility/routes, production permission exclusions, another native client or provider-side behavior. Simulator denial and controller fixtures remain separate earlier evidence.
