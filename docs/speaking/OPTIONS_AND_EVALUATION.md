# Speaking: implementation options and evaluation brief

Prepared **2026-10-16** for B09.1-A / B09.3-A. This is official-source research and an unaccepted evaluation design. No provider is selected, no paid account/service is configured, no audio has been uploaded, and no learner performance is fabricated. The current app has pronunciation playback, not recognition or a recorder UI. [MASTER_PLAN.md](../../MASTER_PLAN.md) owns delivery status.

These are a technical shortlist, not a provider census or benchmark. Feature availability is not evidence of fairness for regional accents or novice speech. Do not compare accuracy using vendor marketing percentages on unrelated data. Native recognition is not exposed by the current `expo-speech` playback service; adding it needs a separate native integration and candidate, not a TypeScript wrapper around playback. Local record/replay can be developed first using the installed audio library and deterministic fixtures, without choosing a hosted service.

Proposed sequence: permission/record/replay/delete and a non-speaking alternative; fixture-driven feedback flow; then one authorized provider/device spike evaluated against the same consented, editor-rated recordings. Keep feedback optional until it provides a demonstrable benefit. This is an engineering recommendation; product/provider/budget acceptance remains B09.1-B.

## Measure before choosing

For each candidate/device/locale/model/version, record cold/warm startup, time from Stop to final result, median/p95 with sample counts, timeout/no-result/cancellation rates, network condition and billable units including retries. Report missing results instead of dropping them from denominators. Local and hosted paths should use identical utterance tasks and recording conditions where technically possible; note any resampling or capture differences.

Use short/long utterances, silence, non-speech, background noise, interruptions, hesitation, self-correction, code-switching, harmless accent variation, plausible alternative replies, correct reference text spoken poorly and a fluent but wrong-task answer. Include different speakers and held-out utterances. A single clean editor recording cannot establish novice performance. Human-rated recordings, consent/rights, phones/headsets and a budgeted test account are inputs still needed.

Evaluate task decisions against independent language judgments, word error rate against a human transcript separately, and any claimed pronunciation dimension against human intelligibility ratings separately. Report disagreement/false rejections and slices with their sample sizes; treat small-sample results as directional. Use a holdout after adjusting rules or thresholds. Define useful latency/cost/error limits with the owner before inspecting results; do not invent numerical acceptance targets now.

## Draft feedback rubric

The teaching goal is communicating a practical message, not imitating one supposedly correct Colombian accent. This rubric needs qualified language/learner review before use as grading.

| Dimension           | Evidence required                                                                                    | Feedback behavior                                                                                                                                               |
| ------------------- | ---------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Task completion     | Accepted intent/required information and legitimate variants, independently judged from the message. | Name the missing or successful practical information. A fluent wrong-task answer does not pass solely because words were recognized.                            |
| Intelligibility     | Human listener can understand the intended message, with recording quality/noise documented.         | Offer one actionable suggestion when justified. Unsupported model certainty or poor input should produce “cannot assess”/retry rather than a low learner score. |
| Phrasing/register   | Reviewed alternatives appropriate for the setting and relationship.                                  | Give an accepted example with context. Allow harmless variations; record use of a revealed model separately.                                                    |
| Transcript matching | Recognizer output versus the human transcript, under named model/locale conditions.                  | Present as a fallible transcript that can be wrong. It must not become a pronunciation score or unaided speaking mastery by itself.                             |
| Practice assistance | Transcript/model/hint used, replay and attempt identity.                                             | Label assisted practice clearly and keep it useful. Do not erase the marker on retry, duplicate rewards/events or change unrelated card scheduling.             |

A response may achieve the task while still benefiting from feedback. Silence, clipped/corrupt audio, unsupported locale, a service failure or an ambiguous result needs an unavailable/redo path. Distinguish those from a judged incorrect response. A local record-and-replay self-check is practice exposure, not assessed speaking evidence.

## AI implementation contract and human inputs

AI can implement a local capture state machine with bounded duration/size, explicit recording/Stop/replay/delete, cancellation on blur/background, permission denial/recovery, no-speech alternative, cleanup and failure fixtures. Microphone/speech permissions are requested only after an explained user action. No background capture, automatic upload or hidden persistence. Until selected and authorized, provider adapters return explicitly synthetic test results only in development/tests and do not produce real assessed speaking history.

For any later hosted path, keep provider credentials server-side; define consent, authentication/authorization, user/global rate and spend limits, timeout/retry/idempotency/cancel semantics, transient upload processing, deletion/retention and log redaction. Audit infrastructure/provider retention and metadata, not just the request body. Capture and server errors need a usable local alternative; cancellation does not imply a provider refunded its work. Use the [commercial model](../product/COMMERCIAL_OPTIONS.md) with measured rates before pricing an allowance.

Owner decisions: supported platforms/OS, provider or strict-local scope, data region/retention, consent wording, operating budget/caps and service access. Human inputs: accepted prompts/variants/feedback, consented recordings with rights, independent task/intelligibility ratings and learner feedback. Physical inputs: microphones, speakers/headsets/Bluetooth, permissions in OS settings, noise/network and actual interrupt/resume behavior. AI fixtures and simulator success do not close those gates.
